How to read the measurements

  • Empty usable space is f_bavail × f_frsize after format and sync. Reserved space is (f_bfree − f_bavail) × f_frsize; EXT4's default 5% reserve is reported separately from metadata.
  • Logical data stored is the actual sum of file lengths after the capacity fill. The writer respects ordinary-user available space even when run as root. ENOSPC, inode exhaustion, metadata constraints and final file size can stop a fill with free blocks remaining. This is workload-dependent capacity, not a universal maximum. A logical-limit stop is a lower bound; sample mode does not measure capacity.
  • Non-file overhead estimate is image size minus f_bfree × f_frsize minus reported file data allocation. It includes journals, filesystem structures excluded from statvfs, directories, inline file data, allocator accounting and other metadata. It excludes ordinary-user reserved free blocks. Filesystems account differently; this is not an exact cross-filesystem metadata counter. Negative or unavailable estimates are omitted.
  • Btrfs metadata used comes from btrfs filesystem df --raw, with DUP multiplied by two. Allocated-but-unused metadata chunks, system blocks, profiles and full usage output are in run details. This counter can include inline file content.
  • File data allocation normally sums st_blocks × 512 for regular files; allocation slack and inline data affect it. Compressed Btrfs uses compsize -b, since st_blocks can misrepresent compressed extent size. No reflinks, hardlinks, sparse copies or deduplication are used.
  • Extent / released savings uses Btrfs's uncompressed extent size minus physical extent size, or F2FS's compression blocks released by ioctl. Other unavailable counters display a dash. F2FS files become non-writable after releasing their reserved compression blocks.
  • Net saved vs baseline compares the reduction in free bytes for the exact same dataset in the uncompressed and compressed runs. It includes changes in metadata and rounding, so can be negative. NTFS compression uses NTFS-3G with LZNT1 and a marked parent directory. Capacity-stage compression values are not compared across different amounts of logical data.
  • Raw image host allocation in details is the backing file's st_blocks, which depends on the host filesystem (including its compression or CoW). It is not the guest filesystem's overhead. Write rates include per-file fsync and F2FS release ioctls; this is a space benchmark, not a device speed benchmark.
